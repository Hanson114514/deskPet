## 2. 本任务目标

运行后能看到：

1. 设置窗口的 `外观`（或 `行为`）组里多一行 **`边缘抗锯齿`** 勾选框，
   **默认未勾选**，提示语**如实**说明收益**与代价**（含"部分素材/档位可能变差"，
   文案真值见 §4），并**带上"重启后生效"**；
2. **未勾选时**：出图与 task14 之前**完全一致**（6 档仍是零重采样的原生硬边），
   这是**回归基线**，必须能证明；
3. **勾选后：全部 10 个档位都经过抗锯齿**（**含 6 档的短路路径**，见 §4 的位置硬要求）；
   **6 档（1.00×）是收益最典型的档位**（它是零重采样档，台阶最硬），
   对照图以它为主角，但**验收必须覆盖 1–10 全部档位**；
   **人物本体（原 alpha=255 的区域）不得被改变**；
4. 勾选后**不出现黑边/白边鬼影**：把结果合成到**纯白**与**纯黑**两种背景上，
   边缘都不得出现"发黑"或"发白"的描边（这是本 task **最容易翻车的一点**，见 §4）；
5. **勾选后走重启流程**：写配置 → **弹询问框**（文案见 §4，**必须写明"可能让部分情况观感变差"**）
   → 同意则重启并生效、不同意则状态栏留下 `重启后生效`；
   **重启后**开关状态与出图**都**是新值；换档、镜像、换动作在开启后仍然正确；
6. **可点范围（mask）语义已放宽**（用户拍板，见 §1）：
   - **允许**可点范围沿人物轮廓**适当扩大**——抗锯齿产生的过渡像素**算作可点**；
   - 凹陷的小结构（小环、发丝之间）**不穿透是预期行为**，**不要求修复**；
   - **只要求**不出现"**大片**幽灵热区"（远离人物的空白区不该可点），
     也不得退化成"整帧可点"（那等于没有穿透）；
7. 开启后**动画节奏不得变差**：本机实测真窗口每帧间隔**不得劣于**开启前的
   **+15%**（基线：§4.9 记录的 41.7 ms/帧；判据见 §6）；
8. `paintEvent` 里补上 `SmoothPixmapTransform`（**独立的一行修复**）：
   DPI≠100% 的机器上不再走最近邻补放大。

## 4. 接口约定

### `deskpet.antialias`

| 符号 | 语义 |
| --- | --- |
| `smooth_edges(image: QImage) -> QImage` | **唯一出口**。输入带 alpha 的图 → 输出边缘带过渡像素的图；**本函数永不抛异常**，任何异常都**原样返回输入**（降级：宁可没抗锯齿，也不能没画面） |
| `DEFAULT_RADIUS` | 过渡带宽度（建议 **1**，先别贪大；见"硬规则"第 5 条） |

**硬规则（逐条实现，逐条验证）**：

| 项 | 约定 |
| --- | --- |
| **1. 守住人物本体** | 原 alpha **= 255** 的像素，输出 alpha **必须仍为 255**；只有边界那一圈才允许出现中间值。做不到这条就是"把整张图糊了"，不是抗锯齿 |
| **2. 必须先膨胀 RGB 再模糊 alpha** | ⚠ **本 task 的头号技术坑**：透明像素的 RGB 通常是垃圾值，**只处理 alpha 会让边缘新产生的半透明像素与背景错误混合 → 出现黑边/白边鬼影**，在浅色背景下**比原锯齿还难看**。必须在边缘处把 RGB 从"最近的不透明像素"**向外扩散（dilate）**之后再合成 |
| **3. 在 premultiplied 空间下操作** | `pet_loader` 已把图转成 `Format_ARGB32_Premultiplied`（`pet_loader.py` 第 757 行）——**沿用它**，不要退化成非预乘格式自己算除法（会引入舍入误差与鬼影） |
| **4. 不改素材** | **绝不**改写 `assets/` 下的 PNG，**绝不**生成新素材文件。全程在内存里做（§0 红线：`assets/` 不得修改） |
| **5. 半径要克制** | 过渡带**建议 1 像素**。加宽会让细节（细发丝、细装饰）变糊，且会明显加重遮罩复杂度（见"性能"第 3 条） |
| **6. 降级** | 空图 / 无 alpha / 尺寸非正 / 任何异常 → **返回输入本身**。与 §2.8 的降级口径一致（可恢复路径永不抛异常） |
| **7. 幂等性不做要求** | 不要求 `smooth_edges(smooth_edges(x)) == smooth_edges(x)`；但**缓存必须保证同一张图只算一次**（否则白烧 CPU） |

### `deskpet.rendering`（修改点）

| 项 | 约定 |
| --- | --- |
| 新增参数 | `FrameRenderer(spec, dpi_scale=1.0, limit=..., antialias=False)`；默认 **False**（守回归基线） |
| **缓存键不加维度** | ⚠ 既然是**重启生效**，开关在**一个进程的生命周期内恒定**，同一个键**永远只会对应一种渲染结果** → **`cache_key()` 保持 4 维不动**（§2.12 的约定原样保留，少改一处就少一处会分叉的地方）。**换屏幕**导致的失效仍按现状由调用方重建 `FrameRenderer` 解决 |
| **⚠ 位置：硬要求，不是待定项** | 抗锯齿的调用点**必须在"缩放 or 短路"的 if/else 之**外**，即**所有档位（含 6 档）都必须流经同一个出口**。写成这个形状：<br>`if (w,h) == target: processed = image`<br>`else: processed = image.scaled(...)`<br>`if self._antialias: processed = antialias.smooth_edges(processed)`<br>**位置由"缩放之后"固定下来**（不要在缩放之前做：那会让放大档被柔化两次）。<br>⚠ **判据**：`smooth_edges()` 的调用**不得出现在 `if/else` 的任何一支里面**——写在支内 = 必然漏掉 6 档（或漏掉其他档位），直接违反 §2 第 3 条。自检要**盯着这个结构**（例如断言"10 个档位开启开关后，渲染结果都 != 关闭时的结果"） |
| **6 档短路分支** | `if (image.width(), image.height()) == target:` 这一支**要保留**（仍然不缩放），但**必须仍然经过抗锯齿**（靠上面的位置要求保证） |
| **⚠ 放大档过度柔化的风险** | 7–10 档本身已经有过渡像素（`SmoothTransformation` 放大产生）。再无条件柔化一次 = **柔化两次** → 细节（细发丝、细装饰）损失比 6 档大得多。<br>**先按"一视同仁"实现（做法 A）**，但**7–10 档必须单独验收"不得明显变糊"**（§6）。<br>**若观感不合格**，退路是做法 B：**检测边缘是否已有过渡像素**，已有就少加或不加。**做成 A 还是 B，看真实对照图再定**（§A.1：先拿事实）。<br>⚠ **不要**为了让放大档"看起来也行"就去改缩放算法（D3 已定案） |
| **各档位收益不同（预期，不是失败）** | 1–5 档是**缩小**，边缘本来就被插值稀释、没有硬台阶可消 → **收益小甚至无**；6 档**收益最大**；7–10 档收益中等。**验收只要求"不劣化"，不要求"每档都变好看"** |
| 缓存上限 | 仍是 `DEFAULT_CACHE_LIMIT = 64`，**不要为抗锯齿放大上限**（开关恒定，两种渲染结果不会并存） |

### 与 mask 的关系（**语义已放宽，见 §1**）

`hit_test.region_for_frame()` 用 `createAlphaMask()`（≈ `alpha >= 128`）。抗锯齿会**新增一圈半透明像素**：

- 这些像素 `>= 128` → 可点区域**沿轮廓略微扩大**；
- `< 128` → 可点区域**不变**，但视觉轮廓已经外扩了。

**两种都被接受**（用户拍板）——**不要求**"看到的边 = 能点的边"严格一致。要做的只有两件事：

| 项 | 约定 |
| --- | --- |
| **允许** | 可点范围沿轮廓**适当扩大**；凹陷的小结构（小环、发丝之间）**不穿透是预期行为**，**不要修** |
| **仍要防** | ① **大片幽灵热区**（远离人物的空白区不该可点）；② **退化成"整帧可点"**（那等于没有穿透，违反 §0 的 `setMask` 决策） |
| **要记录** | 把**实测的偏差量**（可点范围相对视觉轮廓外扩了几个像素）写进 `agent.md`。`rendering.py` 第 14 行的预判**证实或证伪**都可，但**要有数** |
| **别做的事** | **不要**为了"对齐轮廓"去单独调 mask 阈值——那是**另一条独立的路**，用户没要求；本 task 只做抗锯齿 |

### 性能（三条，都要量出来）

1. **日常播放**：走缓存 → 额外开销应**测不出来**（开关恒定，缓存键不变）；
2. **换档瞬间 / 首次取帧**：**按需处理**（取哪帧算哪帧），**绝不**批量预处理全部帧
   （`weedy_sightseer` 有 600 帧的动作，批量会卡）；记录**单帧抗锯齿耗时**；
3. ⚠ **遮罩重绘**：§4.9 已记录"真窗口下遮罩窗口每帧变形状 → 合成器开销，33.6 → 41.7 ms/帧"。
   抗锯齿让边缘半透明像素变多，**可能**进一步加重它。**这一条必须实测**（§6 有判据），
   **不许**凭推理下结论，也**不许**因为这一个数不理想就去改动画逻辑。
