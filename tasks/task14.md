# task14 · 开机自启：状态是真的、开关能关掉、启动文件夹里只有一个文件

## 1. 背景

- **task01–13 已完成**：完整桌宠已可用（窗口、素材、动画、镜像、拖动、久置行为、
  控制栏、音效、双击、设置窗口、全局热键、单实例与重启）。
- 设置窗口里 `开机自启` 那一行目前是**禁用 + `（暂未开放）`**。本 task 把它接上。
- 这一节的坑**与框架无关**，全部来自 Windows 的"启动文件夹"语义，
  所以**行为契约要逐条照做**，不要重新发明。

> **开始前必须先读**：`agent.md`（错误处理方式、可见文字约定）、

## 2. 本任务目标

运行后能看到：

1. 设置窗口里 `开机自启` 那一行**可用**（去掉 `（暂未开放）`），**默认不勾选**，
   且**未勾选时程序完全不动系统里的自启项**；
2. 勾选 → 在用户的「启动」文件夹（`shell:startup`）里出现一个快捷方式 `deskpet.lnk`，
   指向**当前正在运行的这个程序**；状态栏显示 `开机自启：已开启`；
3. 取消勾选 → 自启项被删除；本来就没有 → **幂等成功**；**删不掉必须报错**；
4. 手工把那个 `.lnk` 改坏（读不出目标 / 指向别的程序）→ 状态栏显示
   `未开启［启动文件夹里那个快捷方式是坏的（读不出目标），取消勾选再勾选一次即可重建］`
   或 `未开启［它指向的是别的地方：…］`；
5. 注销/重新登录（或重启）后桌宠**自动起来**；
6. 生成快捷方式失败时（例如安全软件拦住）→ 回退写 `deskpet.cmd`，
   状态文案追加 `［回退方式：登录时会闪一下命令行窗口］`，
   并且**两条尝试各自的原因都要带出来**；
7. 点左下角的 `打开启动文件夹` → 打开那个文件夹（方便用户自己处理）；
8. 开启后「启动」文件夹里**恰好只有一个**我们的文件（不出现 `.lnk` + `.cmd` 两份，
   也不出现任何标记文件）。

## 3. 涉及文件

预计新增：

```

tools/make_shortcut.ps1         生成快捷方式（**外部文件，打包时必须显式声明**）
tools/read_shortcut.ps1         读回快捷方式目标（状态判定的依据）
```

预计修改：

```
src/deskpet/settings.py         解锁"开机自启"行；勾选/取消 + 状态栏刷新
src/deskpet/paths.py            提供"自启项目标"所需的程序路径（**按当前进程反推，绝不写死**）
src/deskpet/logger.py           自启失败要记全原因（两条尝试各自的原因）
```

> **`.ps1` 的编码**：含非 ASCII 字符的 `.ps1` **必须存成 UTF-8 with BOM**，
> 否则 PowerShell 5.1 按系统 ANSI 解码 → 中文乱码 → 语法都过不去 →
> 报一堆 `ParserError`，而用户只看到最后一步的 `Permission denied`（§3.11）。

## 4. 接口约定

### `deskpet.autostart`

| 符号 | 语义 |
| --- | --- |
| `AutostartState` | 结构化状态：`enabled: bool` / `status_text: str` / `error: str \| None` / `detail: str` |
| `query_state() -> AutostartState` | **纯只读**：只读启动文件夹 + 读回快捷方式目标；**绝不写盘、绝不"顺手自愈"** |
| `enable() -> AutostartState` | 开启：先试快捷方式；成功后**清掉可能残留的 `.cmd`**；失败则回退 `.cmd`；**两条失败原因都要带出来**；并提示最可能的原因（安全软件 / 受控文件夹访问）+ 逃生门 |
| `disable() -> AutostartState` | 关闭：删除自启项；本来就没有 → **幂等成功**；**删不掉必须抛错/返回 error**（不许静默吞掉） |
| `startup_dir() -> Path` | `shell:startup` 的解析（可通过 PowerShell 取，或用 `%APPDATA%` 推导并**加断言**) |
| `cleanup_legacy_markers()` | 主动删除早期版本误放在启动文件夹里的标记文件 |

**硬规则（逐条实现）**：

| 项 | 约定 |
| --- | --- |
| 默认状态 | **关闭**。用户不勾选，程序**完全不动**系统里的自启项 |
| 实现 | 在用户的「启动」文件夹放一个快捷方式 `deskpet.lnk` |
| 回退方式 | 生成快捷方式失败 → 写 `deskpet.cmd`（登录时会闪一下命令行窗口） |
| 自我定位 | 运行期按**当前进程**反推：打包后指向 exe 自己；源码运行指向 `pythonw.exe` + 启动脚本。**绝不写死路径** |
| 状态判定 | "**这个功能到底能不能用**"，**不是**"文件在不在"：快捷方式读不出目标、或指向别的程序 → 算**未开启** |
| 读状态只读 | 打开设置窗口、显示状态**不得写磁盘**；"读"与"修"**必须分开** |
| 状态文案 | 见下（**逐字符照做**，属于附录 B 契约） |
| 启动文件夹内容 | 开启后那里必须**恰好只有一个**自启项文件；状态/标记文件一律**不放那里** |
| 启动文件夹清理 | 主动删除早期版本误放的标记文件 |
| 诊断文案 | **不要**写"重新开启即可修正"这种没验证过的承诺（§3.14） |

**状态文案（不可改写）**：

| 情形 | 文案 |
| --- | --- |
| 未开启 | `未开启` |
| 已开启 | `已开启` |
| 快捷方式坏了 | `未开启［启动文件夹里那个快捷方式是坏的（读不出目标），取消勾选再勾选一次即可重建］` |
| 指向别处 | `未开启［它指向的是别的地方：…］` |
| 工作目录不符 | `已开启［工作目录对不上，重新开启即可修正］` |
| 用了回退方式 | `［回退方式：登录时会闪一下命令行窗口］` |
| 状态栏前缀 | `开机自启：` |

**写结果的处理（项目级约定，本 task 是典型场景）**：

- **"清理类"操作可以尽力而为，但"用户明确要求的写操作"必须报错**，
  并把系统给的原因**原样**带出去（`OSError` 原文）；
- 写入失败 → **勾选恢复原样** + 状态栏 `设置失败：<系统原因>`，
  **绝不显示假的成功状态**；
- 控件的"回滚赋值"要**屏蔽信号/加守卫**，避免再触发一次写入。

**与 Qt / 打包的关系**：

- 自启机制**与 Qt 无关**，`shell:startup` + 快捷方式 + `.cmd` 回退照旧；
- **待决策（不建议改）**：是否改用注册表 `Run` 键或 `QSettings`——
  现有的失败诊断文案与逃生门都建立在启动文件夹上，**建议保持**；
- 打包相关：`.ps1` 是**外部文件**，打包数据必须**显式声明**；
  漏掉的表现是"开机自启永远显示不可用"，而**源码运行看不出来**（§3.8）。
  本阶段不打包，但要在 `agent.md` 里记下这条待办。
