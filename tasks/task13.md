## 2. 本任务目标

运行后能看到：

1. 桌宠已经在跑时再双击启动 → **什么都不发生**，第二个进程**安静退出**（返回 0，不弹任何错误）；
2. `python run.py --list-pets` / `--list-actions` / `--list-sizes`
   在"已经有一个在跑"时**仍然能正常输出并退出**（只读查询不该被拒）；
3. 在**另一个 Windows 用户**下登录并启动 → 可以各跑一个（作用域仅当前登录会话）；
4. 保护机制不可用时（人为让 API 起不来）→ **不阻断启动**，
   日志里说明"少了这层护栏"；
5. 设置里选一个**可用**的角色 → 配置写入 → 弹"现在自动重启吗？" → **同意**：
   旧实例消失、**新实例自动起来**并显示新角色（中途**不会出现"点了重启桌宠没了"**）；
6. **不同意**重启 → 提示"重启后生效"，当前实例继续运行；
7. **重启失败**（例如故意把新进程启动路径改错）→ 弹窗
   `重启失败，请手动关掉再启动一次`，并且**当前实例不退出**；
8. 重启成功后，**新实例的表现为**：等待 `--restart-delay`（默认 **1.2 秒**）后再抢单实例锁
   （日志里能看出这个时序）。

## 4. 接口约定

### 单实例（`deskpet.single_instance`）

| 符号 | 语义 |
| --- | --- |
| `acquire() -> SingleInstanceHandle \| None` | 成功 → 句柄；**已有实例 → None**（调用方安静退出，返回 0） |
| `SingleInstanceHandle.release()` | **主动放锁**（重启路径必须调用） |
| `is_available() -> bool` | 保护机制能不能用；`False` 时**不阻断启动**，只记日志 |
| 作用域 | **仅当前登录会话**（同一台机器的另一个用户可各自跑一个） |
| 机制 | 按 **D6** 择一：`QLocalServer`（平台无关）或**命名互斥体**（`ctypes` + `CreateMutexW`） |

**启动顺序硬约束**（§13 + §16）：

```
解析命令行
 └─ 装日志（尽早）
     ├─ --list-pets / --list-actions / --list-sizes     ← 只读查询，最先
     └─ 初步自检 + 退回默认形象
 → 加载素材（打开图集）
 → 单实例保护            ← 放在只读查询**之后**
 → 建窗口 …
```

- `--list-*` **必须早于**单实例检查；
- 若走 `QLocalServer`：套接字文件路径**不要**算进"用户数据目录"的契约，也不要在那里放状态文件（§3.1 的教训）。

### 重启自己（`deskpet.restart`）

| 符号 | 语义 |
| --- | --- |
| `RESTART_DELAY_DEFAULT = 1.2` | `--restart-delay` 的默认秒数 |
| `restart_self(handle) -> bool` | 拉起新实例 → **成功才**放锁 → 关闭自己；失败**不退出** |
| `build_args() -> list[str]` | 新进程参数；**必须含 `--restart-delay <秒>`** |
| 新进程行为 | **先等 `--restart-delay` 再抢单实例锁** |
| 子进程要求 | **完全脱离**父进程：不继承标准流、独立进程组/会话；工作目录固定为**程序目录** |
| 顺序 | **先拉起新实例，再关闭自己**（反过来会来不及：进程正在消失，子进程可能被一起带走） |
| 失败 | 弹窗 `重启失败，请手动关掉再启动一次`，**不退出当前实例** |
| 交接 | **两边一起兜住**：新进程等 1.2 秒 + 旧进程**主动放锁** |
| 实现 | `QProcess.startDetached(program, args, working_dir)`；**不要**用 `QProcess.start()`；**必须真判返回值**（`False` 按失败处理） |

### 换角色流程（设置窗口 → `task11` 的边界在这里补齐）

| 情形 | 行为 |
| --- | --- |
| 选到**可用**包 | 写配置 → 询问"现在自动重启吗？" → 同意才重启；不同意则提示"重启后生效" |
| 选到**坏包** | 弹窗说明"你的选择没被接受、已回到默认形象"，**提供详情**，**不重启**，**同时把配置改回默认形象** |
| 配置写失败 | 提示"保存失败，重启后会回到原来的角色"，并且**界面显示必须与真实生效的一致** |
| 默认形象 | 只在**一处**写真值（`pet_spec` 的常量）；配置默认值是空串 |
| 换形象方式 | **走重启**，不做热替换（`cell` 可能不同；热替换会留下"状态半新半旧"的中间态） |

## 5. 不要做

- ❌ 不做"开机自启"（task14）
- ❌ 不做热替换角色（**明确约定走重启**）
- ❌ 不做多实例协调 / 进程间通信（除了"发现已有实例就退出"）
- ❌ 不做"重启后恢复上一次的临时状态"（档位与位置本来就在配置里）
- ❌ 不做自动更新 / 版本检查
- ❌ 不写死路径（运行期按当前进程反推：打包后指向 exe；源码指向 `pythonw.exe` + 启动脚本）
- ❌ 不用 `QProcess.start()`（父进程退出会带走子进程）
- ❌ 不把单实例检查放到 `--list-*` 前面
- ❌ 不为了"更快重启"把 1.2 秒改小或去掉（这是交接的关键）

## 6. 验收标准

- [ ] 桌宠已在运行时再启动一次：第二个进程**安静退出**，
      **没有弹窗**、没有错误对话框，`echo $LASTEXITCODE`（或等价检查）为 **0**
- [ ] 桌宠已在运行时执行 `--list-pets` / `--list-actions` / `--list-sizes`：
      **正常输出并退出**（不被单实例拒绝）
- [ ] 日志里能看到第二个进程"检测到已有实例，退出"的记录
- [ ] 关闭所有实例后启动：正常起来（锁被正确释放）
- [ ] 人为把保护机制弄成不可用（例如让创建互斥体/本地服务的调用失败）→
      **程序照常启动**，日志里有"少了这层护栏"的说明
- [ ] 在另一个 Windows 用户下启动：**可以各跑一个**（验证作用域）
- [ ] 设置里选**可用**角色 → 同意重启：
      **旧实例消失、新实例自动起来并显示新角色**，中间**不出现"桌宠没了"**
- [ ] 重启后的日志里能看到：新进程**先等约 1.2 秒**，再抢锁成功
- [ ] 不同意重启：提示"重启后生效"，**当前实例仍在运行**
- [ ] 注入重启失败（把子进程程序路径改成不存在的路径）→
      弹窗 `重启失败，请手动关掉再启动一次`，**当前实例不退出**（还能继续用）
- [ ] 设置里选**坏包**：提示详情 + 退回默认形象 + **不重启** +
      **配置被改回默认形象**（重启后不再踩同一个坑）
- [ ] 界面显示的当前角色与**真实生效**的角色一致（写入失败时不能显示假成功）
- [ ] 配置写失败时提示"保存失败，重启后会回到原来的角色"
- [ ] 新进程**完全脱离**：在任务管理器里确认新实例的父进程不是旧实例（旧实例已退出）；
      关闭父进程的窗口/控制台**不会**连带关掉新实例
- [ ] 新实例的工作目录是**程序目录**（日志里记录 `Path.cwd()` 验证）
- [ ] 连续重启 5 次（来回换角色）：**没有出现两个实例同时存在**，也没有"没有实例"的空窗
- [ ] 重启后：**档位与位置沿用**（因为它们存在配置里，不需要额外处理）
