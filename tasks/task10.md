## 2. 本任务目标

运行后能看到/听到：

1. **启动后约 80 ms** 发出一声启动音（`chime`；**两个自带包都没有 `sounds`** → **静默**；
   要给某个包补上 `"chime": "文件.mp3"` 才听得到）；
2. 点右键菜单 `坐下休息` → **有休息的音效**（`rest`；同样需要素材声明）；久置自动休息 → **同样有音效**；
3. 拖动音量滑块（本 task 可用手改 `config.json`）→ **已打开的播放器音量立刻变化**，
   不需要重启；
4. **双击宠物** → 宠物站立并**完整播放一次 `waving`**（抬手 → 收手），同时播放 `chime`；
   播完自动回 `idle`；
5. **拖动途中双击被忽略**（不会一边拖一边挥手）；
6. 把 `sounds` 里声明指向一个**不存在的文件**、或把一个**打不开的格式**放进 `sounds/`、
   或往 `sounds/` 里塞一个**没声明的**文件 → 程序**照常运行且无声音**，
   日志/诊断里能看出这三种情况；
7. 汇报文案与约定一致：`音效 2/2` / `无音效` / `无音效（未在索引里声明：bgm.mp3）` /
   `音效 1/2（缺 rest）（无法播放：bgm.ogg）`。

## 4. 接口约定

### 逻辑名与映射（**只有两个逻辑名**）

| 逻辑名 | 用途 |
| --- | --- |
| `rest` | 主动休息 + 久置自动休息**共用**（旧名 `sit`，随动作改名） |
| `chime` | **启动音** + 双击交互音 |

**映射规则（逐条实现）**：

| 规则 | 约定 |
| --- | --- |
| 来源 | **只由素材索引 `sounds` 声明决定**：`{"rest": "文件.mp3", "chime": null}` |
| 不猜文件名 | **没有兜底表**、不自动认 `sounds/rest.mp3`；没声明就是没有声音 |
| 值语义 | `null` 或空串 = 这个包确实没有这个音效，**与没写这个键等价**（task03 的解析层把 `null` 记成空串） |
| 坏数据 | 键或值类型不对 → **丢弃**（只该变成"没声音"，不该让程序起不来）。**task03 已实现**：这类坏数据只进 `warnings`，不进 `issues` |
| 文件名 | 相对 `sounds/` 目录；不存在 → 计入"缺"（不抛异常） |

### `SoundPlayer`（`deskpet.sounds`）

| 符号 | 语义 |
| --- | --- |
| `SoundPlayer(spec, volume)` | 按素材包构建；读 `sounds` 声明 |
| `preload() -> None` | **异步预热**（见下"不能阻塞"） |
| `play(name: str) -> None` | 播逻辑名；**任何一步失败 → 静默跳过** |
| `set_volume(value: int)` | 0–100；**立刻作用到已打开的播放器** |
| `volume -> int` | **播放器持有当前音量**（设置界面从它读，task11 用） |
| `available -> bool` / `unavailable_reason -> str` | 优雅退化：**可用标志变 False + 记下原因** |
| `close()` | 关闭全部播放器，避免句柄泄漏 |
| `diagnose() -> SoundReport` | 三条诊断可见性（见下） |
| `summary() -> str` | 汇报文案（`音效 2/2` 等，**格式不可改**） |

**行为契约**：

| 项 | 约定 |
| --- | --- |
| 音量 | 配置 `volume`，量程 **0–100**，越界**夹取**；`"x"` 之类非法值归 **0** |
| 设备类型 | **旧实现"按扩展名给 MCI 设备类型"那张表整体删除**；扩展名判断只在"要不要尝试播放"这一层保留 |
| 预加载 | 启动时**异步**预热（首播会卡顿）；**不要**复制旧实现的"专属音频线程"结构 |
| 启动音时机 | 等预热有结果（**超时 2 秒**）后播 `chime`，启动后约 **80 ms** 触发 |
| 重复触发 | 同一音效再次播放要**先回到起点**再播，避免叠加 |
| 优雅退化 | 任何一步失败只是"没有声音"：可用标志变 False、记原因，**绝不让程序起不来** |
| 退出 | `close()` 关闭全部播放器（挂在 `aboutToQuit` / `closeEvent` 上） |
| 诊断可见性 | ① 索引声明了但**文件不在**；② `sounds/` 里**格式打不开**；③ `sounds/` 里**存在却没声明** |

**"不能阻塞"是本 task 的新要点**：旧实现"后台线程预加载 + 主线程播放"的前提是 MCI；
Qt 路线的实现**必须**在事件循环里异步推进：
`QTimer.singleShot(80, ...)` 触发启动音，预热结果用**信号**回来，
超时 2 秒用**另一个定时器**兜底。**不要**在主线程里 `sleep` 或忙等。

**播放器线程约定**（Qt 相关，必须写进 `agent.md`）：
所有播放器调用**都在 GUI 线程**；`QMediaPlayer` **不是线程安全的**，
不要从别处直接调它。**保留旧教训的方法论**："所有设备调用走同一条确定路径"
+ "测试必须走产品实际使用的那条路径"。

### 双击手势（清单第一部分 §3）

- 双击 → 播放 `waving` **整段一次**（等价 `("loop", 1)`），播完回 `idle`；
- **不裁帧**：首帧是抬手（起势）、末帧是收手（收势），衔接 `idle` 更自然；
- 同时播 `chime`；
- **拖动途中双击被忽略**；
- 已知代价：`waving`（旧名 `jumping`）的人物被素材画成约 **74.5%** 大小，进出各有约 26% 的尺寸变化；
  **不在运行时缩放它去对齐尺度**（素材固有特性）。

## 6. 验收标准

> **前置**：两个自带包**都没有 `sounds` 声明**，所以"能听到声音"的条目需要**先给某个包
> 补上 `sounds`**（那属于改素材，**要用户同意**）。在此之前，可自动化的验收是
> "无音效 + 不崩 + 诊断文案正确"这一组。

- [ ] 给某个包补上 `"chime": "文件.mp3"` 后，启动约 80 ms 能听到 `chime`
- [ ] 用 `--pet weedy`（无音效）启动：**没有任何声音**，程序正常运行，日志里有"无音效"及原因
- [ ] 点 `坐下休息` → 有 `rest` 音效；等久置自动休息 → **同样**有 `rest` 音效
- [ ] **双击**宠物 → 播放 `chime` + 完整挥手一遍（起势→收手→回 idle）
- [ ] 拖动途中双击 → **不挥手、不响**，拖动不受影响
- [ ] 双击后立刻再双击 → 不叠加成怪声（重播先回起点）
- [ ] 手改 `config.json` 的 `volume` 为 `0` → 无声；为 `100` → 明显大声；
      为 `1000` → 夹到 100；为 `"大声"` → 归 0；**改完立刻生效，不用重启**
- [ ] 音量值在**运行时**可从播放器读回（为 task11 的滑块准备）
- [ ] 把 `sounds` 里 `rest` 改成 `"没有这个文件.mp3"` → 无声音但**不崩**，
      诊断里能看到"声明了但文件不在"
- [ ] 往 `sounds/` 放一个**能打开但没声明**的文件（如 `bgm.mp3`）→ 汇报文案变成
      `无音效（未在索引里声明：bgm.mp3）` 这类形态
- [ ] 往 `sounds/` 放一个**打不开**的文件（例如改名的 txt）→ 无声音、不崩、诊断能看出
- [ ] 把 `sounds` 写成 `["rest"]`（类型不对）→ 丢弃 + 警告，**不崩**
- [ ] 汇报文案四种形态都实测过一次，与约定**逐字符一致**
- [ ] 启动时**不卡**：从双击图标到窗口出现、动画开始播放，没有可感知的停顿
      （首播预热生效）
- [ ] 退出程序后**没有残留进程**占用音频设备：立刻再启动一次，音效仍然正常
- [ ] 长跑：休息/双击重复 50 次不出现"后续没声音"（设备句柄泄漏的表现）
