# task08 · 拖动与命中：只有按在人物身上才起拖，松手记住位置

  动画播放、右键菜单（含镜像翻转）、**久置行为状态机**（含"动作控制权可被挂起"的接口）。

  **只有按在人物身上才起拖**、按水平方向切跑动动作、松手把落脚点写进配置。
- 本 task 同时是**点击穿透方案（附录 D 的 D2）真正落地的地方**：
  要么 `setMask(QRegion)`，要么自己按 alpha 判定，要么两者混合。

## 2. 本任务目标

运行后能看到：

1. 在**人物身上**按住左键拖动 → 窗口跟手移动；在**透明区域**按住拖动 →
   **不拖宠物**（鼠标事件穿透到下面的窗口/桌面）；
2. 拖动过程中宠物播放 `running_left` / `running_right`（**按水平位移方向**决定，
   没有速度阈值，慢速拖动不会来回闪）；
3. 松手后回 `idle`，并且 **`data/config.json` 的 `position` 被写成落脚点**（`"x,y"`）；
4. 重启程序 → 宠物**出现在上次拖动后的位置**（不再贴右下角），启动信息里来源显示"沿用上次"；
5. 把宠物拖到屏幕边缘再松手 → **位置被夹回屏幕内**，且写进配置的也是**夹取后**的值；
6. 拖动途中**双击被忽略**（不会一边拖一边跳）；
7. 拖动时指针变成"移动"形状，松手还原；
8. **`manual` 坐姿期间拖动** → 自动退出 `manual` 模式（拖完回 `auto`）；
9. 拖动过程中**静置逻辑不插手切动作**（动作不会闪一下）。

## 4. 接口约定

### 命中判定（`deskpet.hit_test`）

| 符号 | 语义 |
| --- | --- |
| `hit_test(frame_image, pos: QPoint, rendered_size, mirrored: bool) -> bool` | **唯一入口**。"取哪一帧的图"与"怎么判定"**分开** |
| `region_for_frame(frame_image, mirrored: bool) -> QRegion` | 若走 `setMask`：按当前帧的不透明像素生成窗口区域（**只在这一处生成**） |
| 坐标 | **窗口内的物理像素**；镜像时 `x' = width - 1 - x` |
| 无遮罩 / 坏数据 | **整帧可点**（手写素材包少一个可选文件不该变成拖不动） |
| 帧号越界 / 动作不存在 | **整帧可点** |
| 性能 | 判定结果**按帧缓存**；换帧/换档/**换镜像**都必须失效 |

**必须保留的降级语义**（无论 D2 选哪条）：任何一步算不出来 → **退化为整帧可点，永不抛异常**。

### 拖动（`deskpet.drag`）

| 符号 | 语义 |
| --- | --- |
| `DragState` | `pressed` / `base_pos`（按下时的窗口位置，**权威位置**）/ `grab_offset`（鼠标在窗口内的偏移）/ `last_direction` |
| `begin(local_pos, global_pos, window_pos)` | 按下；**只有 `hit_test` 通过才进入拖动** |
| `update(global_pos) -> (new_pos, action_or_None)` | 用**自己记的基准位置**算位移；返回新位置与"该播哪个动作" |
| `finish() -> QPoint` | 松手；返回最终位置（调用方负责夹取 + 写配置） |
| `direction_action(dx, last) -> str` | **纯函数**：只看 `dx` 的**符号**，**不设速度阈值**；纯竖直移动沿用 `last`；没有方向依据时以 `running_right` 起跑 |
| `drag_started` / `drag_finished(pos)` 信号 | 开始/结束拖动（供控制栏增量跟随、静置逻辑挂起/恢复使用） |

**硬规则**：

- **禁止回读窗口实时坐标**（`pos()` / `geometry()`）；位移一律用 `base_pos + (当前全局 − 按下全局)`；
- "**只点了一下没拖动**"也要做一次**完整的位置校正通知**（处理"拖到边缘被夹住、位置没变但仍需同步"）；
- 拖动中**不逐帧写配置**（只在松手与换档时写）；
- 拖动结束/夹取后，写进配置的必须是**夹取后**的值（§3.19：**夹取发生在存进权威位置之前**）；
- 用户拖动过之后，缩放**不得弹回右下角缺省落点**（位置一旦由用户决定就以它为准）；
- **拖动开始**：调用 task07 的挂起接口（动作控制权归拖动逻辑）+ **归零静置计时**；
  **拖动结束**：恢复挂起 + 再归零一次。

### 事件映射（Qt）

| 交互 | 处理器 |
| --- | --- |
| 左键按下 | `mousePressEvent(QMouseEvent)` |
| 拖动 | `mouseMoveEvent`（要在按下之后才认作拖动） |
| 松手 | `mouseReleaseEvent` |
| 双击 | `mouseDoubleClickEvent`（本 task 只做"拖动途中忽略"） |
| 右键 | `contextMenuEvent`（task06 已接） |

- 位移用 `event.globalPosition()`；命中判定用 `event.position()`，**两者不可混用**；
- 指针形状：拖动中 `setCursor(...)`，松手 `unsetCursor()`。

### 位置决定顺序

`命令行 --position` > `上次保存的`（用 `has("position")` 判定）> **缺省贴右下角**（边距 24）。

- 命令行 `--position` 非法 → **当场报错退出**；
- 配置里 `position` 格式不对/不是整数 → **忽略并记一行日志，不报错、不影响启动**。

对上 §7 那几条的答复：

1. **D2 最终落地 = `setMask(QRegion)`**，没有自判定、没有混合。唯一实现是
   `hit_test.region_for_frame()`；`pet_window.region_for_image()` 只剩转发。
   区域**只在换帧 / 换档 / 换镜像时重算**，同动作同档位内复用；实测**没有抖动**
   （120 次完整拖动期间心跳定时器照常跑，位置每步都精确命中理论值）。
2. **"透明区真的穿透"的验证方式**：真平台 Win32 `WindowFromPoint` ——
   人物中心 → 本窗口，窗口四角 → **全部是别的窗口**（4/4）。
   **没有垫记事本**：`WindowFromPoint` 返回别的窗口本身就证明点击落不到宠物上，
   比"垫一个程序再肉眼点"更硬，而且可自动化（§4.9 说这是唯一可自动化的判据）。
3. **`setMask` 的边缘锯齿**：用 1 位 alpha 的真实素材观察确有台阶，与 task01 占位矩形的
   结论一致（1 倍观察几乎看不出）。它是 §0 已定案的取舍，**本 task 未解决**——
   源 GIF 的 alpha 本来就是 1 位（§4.12），已记进 agent.md。
4. **挂起接口最终叫 `PetWindow.set_action_suspended(bool)`**（转发到
   `IdleStateMachine.set_suspended()`）。恢复时**重新计时**。
5. **实际新增/修改的文件与卡片预计的有出入**，见 §3 末尾。

**顺带修掉两个真 bug**（都是自检抓到的，不是猜的）：

- **双击把宠物卡住**：Qt 顺序是 press → release → dblclick，双击的第 2 次按下会先触发
  `mousePressEvent`，把"拖动"顺手开起来且没有配对的松手 → `dragging` 恒为真
  （右键菜单永远不弹、静置逻辑永远被挂起）。**task07 的自检当场抓到**。见 agent.md §4.16。
- **无 `QGuiApplication` 时 `QBitmap.fromImage()` 直接段错误**（`0xC0000005`，
  `try/except` 拦不住）。对策 `hit_test.can_build_region()`。见 agent.md §4.15。
