# task04 · 尺寸档位与缩放：10 级都能变、贴边不跑出屏幕

## 1. 背景

- **task01–03 已完成**：透明置顶窗口可拖可退；`data/` 配置与日志可用；
  素材加载链路可用，窗口能显示**真实素材的静态第一帧**（原始 250×250）。
- 本 task 加入**尺寸模块**：10 级档位、屏幕自适应、右下角锚点缩放，并提供
  `--size-level` 与 `--list-sizes` 两个命令行入口。

> **开始前必须先读**：`agent.md`、`迁移清单.md` 第一部分 §4（尺寸，尤其"缩放的两条硬规则"）、
> 第二部分 §7（帧的画布规格与缩放算法，含**附录 D 的 D3**）、
> 第三部分 3.19 / 3.21、附录 C（数值常量）。

## 2. 本任务目标

运行后能看到：

1. `python run.py` 启动时，宠物**按屏幕自适应**选出一个档位：
   在 1080p + DPI 缩放 125% 的机器上应该是**第 6 级（1.00x）**；
2. `python run.py --size-level 1` 与 `--size-level 10` 分别显示**最小与最大**的宠物，
   且**右下角的位置不变**（脚底与右边都不动，向"左上"方向长大）；
3. `python run.py --size-level 11`（或 `0`）**当场报错退出**；
4. `python run.py --list-sizes` 打印 10 个档位的倍数、像素尺寸、
   **当前屏幕的自适应档位**，然后退出；
5. 在 `config.json` 里写 `"size_level": 10` 后重启 → 沿用**第 10 级**；
   把这项**删掉**后重启 → 回到**按屏幕自适应**（这就是"必须能区分没设过与设成默认值"的用处）。

## 4. 接口约定

### 尺寸（`deskpet.size`）

| 符号 | 语义 |
| --- | --- |
| `LEVEL_COUNT = 10` | 档位数量 |
| `DEFAULT_LEVEL = 6` | 默认档位（1.00×）；**配置默认值必须引用它，不许另写一个 `6`** |
| `LEVEL_RATIOS: tuple[tuple[int, int], ...]` | 每级 `(zoom, subsample)` **精确有理数**：0.25 / 0.333 / 0.5 / 0.666 / 0.75 / 1.00 / 1.25 / 1.333 / 1.50 / 2.00 |
| `clamp_level(level: int) -> int` | 夹到 `1..LEVEL_COUNT` |
| `ratio_of(level: int) -> float` | 该级倍数（**展示用**；像素计算**不要**用它，要走有理数） |
| `pixel_size(cell: tuple[int, int], level: int) -> tuple[int, int]` | 帧实际尺寸 × 倍数，**向下取整** |
| `level_for_screen(screen_height: int, cell: tuple[int, int]) -> int` | 选使"宠物高度 ÷ 屏幕高度"最接近 **0.24** 的档位（**按高度不按宽度**） |
| `SCREEN_TARGET_RATIO = 0.24` | 屏幕占比目标 |
| `DEFAULT_MARGIN = 24` | 默认落点距屏幕边缘的逻辑单位 |
| `CALIBRATION` | 标定基准常量：1080p + DPI 1.25 → 第 6 级（**断言用常量，不读当前屏幕**） |

**硬规则（逐条实现，逐条验证）**：

1. 10 级尺寸**互不相同且严格递增**（要能断言，不能有两个档位塌缩到同一像素尺寸）；
2. **右下角锚点不动**：第 1..10 级之间右下角坐标漂移必须为 **0**；
3. **每一步都不能被挤出屏幕**；
4. 窗口尺寸 / 内容尺寸 / 精灵渲染尺寸**三者对齐**（同一次 DPI 换算）；
5. 屏幕越高，选出的档位**不得变小**（单调性）；
6. 档位越界 → 夹到 1..10；但**命令行**越界必须**被拒**（两条不同规则，别混）。

### 渲染（`deskpet.rendering`）

| 符号 | 语义 |
| --- | --- |
| `FrameRenderer(spec, dpi_scale)` | 负责"帧 → 目标尺寸的可绘制对象" |
| `renderer.frame(action: str, index: int, level: int) -> QPixmap` | 取缩放后的帧 |
| 缓存键 | `(动作, 帧序号, 档位)` —— **本 task 只有这三个维度**；task06 加入**镜像**时**必须**同步改键（否则"翻转后拿到未翻转的缓存图"） |
| 缩放算法 | 按 **附录 D 的 D3** 定：`SmoothTransformation` 或三倍最近邻。**放大只在换档/加载时做，不能每帧做** |
| 缓存上限 | 需要有一个明确上限（LRU 或按"当前档位 + 前一档"保留），避免来回切档把内存吃满 |

### 命令行（本 task 新增）

| 参数 | 约定 |
| --- | --- |
| `--size-level 1..10` | 越界**当场报错退出** |
| `--list-sizes` | 列出 10 级（倍数、像素尺寸）+ 当前屏幕尺寸 + 自适应档位；**依赖 `cell`，因此在加载素材之后** |

- 启动信息里必须打印：**档位 + 来源（命令行指定 / 沿用上次 / 按屏幕自适应）+ 像素尺寸**。
- 档位决定顺序：**命令行 > 上次保存的（用 `has("size_level")` 判定）> 按屏幕自适应**。

## 5. 不要做

- ❌ 不做帧播放/帧率消费（仍显示静态帧；动画是 task05）
- ❌ 不做尺寸控制栏 UI（`−` / `+` / `×` 那个悬浮条是 task09）
- ❌ 不做拖动、不做位置持久化（**位置**持久化属于 task08；
      本 task 只需要"按档位摆放/缩放时锚点不动"）
- ❌ 不做镜像翻转（task06）
- ❌ 不做命中判定/穿透的最终方案（task08）
- ❌ 不做设置窗口里的尺寸入口（task11）
- ❌ 不改素材、不改 `cell` 的语义（`cell` 永远是**帧文件实际像素尺寸**）
- ❌ 不用 `float` 累乘做档位换算（要用 `zoom/subsample` 的精确有理数）

## 6. 验收标准

- [ ] `--list-sizes` 列出 10 行；倍数显示为 `0.25` … `2.00`；
      **10 行的像素尺寸两两不同且严格递增**
- [ ] 断言"1080p + DPI 1.25 → 第 6 级"用**常量基准**通过（不读当前真实屏幕）
- [ ] 在本机跑 `--list-sizes`：输出里的自适应档位与启动时实际选中的档位**一致**
- [ ] 在 1080p 屏上启动：宠物高度约占屏幕高度 **24%**，档位为 6（若你的屏幕不是 1080p，
      记录实际值并在 agent.md 里注明"与标定基准不同，属正常"）
- [ ] 依次启动 `--size-level 1` … `--size-level 10`：
      **右下角坐标（右边缘 x、下边缘 y）逐级完全一致，漂移为 0**
- [ ] 每一级都**完整可见**：没有半截跑出屏幕、没有被任务栏挡住
- [ ] 窗口边缘**没有留白**（窗口尺寸 = 缩放后的内容尺寸），也没有裁边
- [ ] `--size-level 0` / `--size-level 11` / `--size-level abc` → 当场报错退出（不是夹取、不是崩溃）
- [ ] 配置写 `"size_level": 10` → 启动沿用第 10 级，启动信息里来源显示"沿用上次"
- [ ] **删掉** `size_level` 这一项 → 启动回到"按屏幕自适应"，来源显示"按屏幕自适应"
- [ ] 配置写 `"size_level": 6`（等于默认值）→ 启动**仍显示"沿用上次"而不是"自适应"**
      （这一条专门盯"没设过 vs 设成默认值"的判定）
- [ ] 反复切档 20 次（1↔10）：**不卡顿、不闪白、不裁边**；内存不持续增长（缓存有上限）
- [ ] 档位从 1 变到 10 时，肉眼看到的是"向左上长大"，**脚底与右边不动**
